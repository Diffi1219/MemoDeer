# AI 产品模型选型报告

> 产品：知道AI学习助手（MemoDeer）
> 报告生成时间：2026-07-14
> 评估依据：各厂商官方文档、公开评测数据、场景需求分析

## 1. 需求摘要

| 项目 | 内容 |
|------|------|
| **业务场景** | AI 学习助手：知识点提取、智能出题、记忆口诀生成、RAG 检索增强问答 |
| **目标用户** | 大学生、考研、考公等独立备考者 |
| **核心能力** | ① 知识库构建（PDF/图片上传 → 知识点提取）<br>② 智能出题（选择题、填空题 + 记忆口诀）<br>③ RAG 检索增强问答（有据可依的解答） |
| **技术架构** | 三模型协同：本地小模型（RAG 检索/语义匹配）+ 云端长上下文模型（超长文档兜底）+ 云端大模型（推理/生成） |
| **部署要求** | RAG 小模型本地部署（数据不出服务器）；推理大模型 API 接入 |
| **合规要求** | 教育场景，需基础内容安全；用户学习数据需加密存储 |
| **预算约束** | 学生创业项目，成本高度敏感，月度预算有限 |
| **其他约束** | 中文场景为主；需支持长上下文（教材片段）；低延迟（学习体验流畅） |

## 2. 候选模型对比表

### 2.1 场景权重定义

本产品属于 **C 端教育工具**，结合「成本敏感 + 效果优先 + 数据隐私」特点，权重调整如下：

| 维度 | 权重 | 说明 |
|------|------|------|
| 效果质量 | 25% | 出题质量、口诀创意、解答准确度直接影响学习效果 |
| 性能表现 | 15% | 学生高频使用，需稳定响应 |
| 延迟体验 | 15% | 学习场景交互性强，等待过久影响学习节奏 |
| 成本经济 | 20% | 学生项目预算有限，成本是核心约束 |
| 合规安全 | 15% | 教育场景，用户学习数据隐私是重点（权重提升） |
| 部署集成 | 10% | 需要本地部署 RAG 模型（权重提升） |

### 2.2 架构设计：三模型协同

```
用户提问
  │
  ▼
┌─────────────────────────────┐
│  Qwen3-8B（本地部署）        │  ← RAG 主力：知识点提取、语义检索、query 改写
│  128K 上下文 · 零 API 成本   │     覆盖 95% 场景（单本教材 ≤128K）
│  数据不出服务器               │
└─────────────┬───────────────┘
              │
              │ 如果文档 > 128K（整本书/长篇论文）
              ▼
┌─────────────────────────────┐
│  DeepSeek-V4-Flash（API）    │  ← 长文档兜底：超长教材知识点提取
│  1M 上下文 · 按量付费        │     仅在超出本地模型能力时调用
└─────────────┬───────────────┘
              │
              │ 检索结果 + 用户问题
              ▼
┌─────────────────────────────┐
│  DeepSeek-V4-Pro（API）      │  ← 推理生成：出题、解析、口诀、问答
│  1M 上下文 · 384K 输出       │     所有需要强推理的任务
│  支持思考模式                 │
└─────────────────────────────┘
```

**设计原则**：
- **能本地就不上云**：RAG 检索用本地 Qwen3-8B，零成本且数据隐私有保障
- **按需降级**：仅当文档超长时才调用 V4-Flash API
- **推理上云**：出题/解析等强推理任务交给 V4-Pro，质量有保障

### 2.6 调用量与月度成本估算

假设场景：
- 日活用户 100 人，每人每天 5 次学习 session
- 每次 session：RAG 查询 3 次 + 推理调用 2 次
- **95% 场景文档 ≤128K**，由本地 Qwen3-8B 处理（零 API 成本）
- **5% 场景文档 >128K**，由 V4-Flash API 处理

**RAG 模型成本**：

| 方案 | 月调用量 | 月成本 | 说明 |
|------|----------|--------|------|
| **Qwen3-8B 本地**（95%） | ~85.5M tokens | **0 元**（仅 GPU 算力） | 数据不出服务器 |
| V4-Flash API（5%） | ~4.5M tokens | **约 7 元** | 长文档兜底 |
| **RAG 总计** | 90M tokens | **约 7 元** | — |

> 对比：如果 RAG 全部走 API（V4-Flash），月成本约 135 元；本地部署省了 **128 元/月**。

**推理模型成本（V4-Pro API）**：

| 场景 | 月调用量 | 月成本 |
|------|----------|--------|
| 无缓存（最坏） | 90M tokens | **510 元** |
| 50% 缓存命中 | 90M tokens | **257 元** |
| 80% 缓存命中 | 90M tokens | **103 元** |

> 计算：90M × (0.003×0.67 + 0.006×0.33) = 510 元（无缓存）
> 教育场景知识库内容重复度高，缓存命中率预计可达 50-80%

**总成本汇总**：

| 场景 | RAG 成本 | 推理成本 | GPU 算力成本 | 总月成本 |
|------|----------|----------|-------------|----------|
| 无缓存 + 云 GPU | 7 元 | 510 元 | 800 元 | **1,317 元** |
| 50% 缓存 + 云 GPU | 7 元 | 257 元 | 800 元 | **1,064 元** |
| 无缓存 + 自有 GPU | 7 元 | 510 元 | 0 元 | **517 元** |
| 50% 缓存 + 自有 GPU | 7 元 | 257 元 | 0 元 | **264 元** |

> GPU 算力成本说明：
> - 云 GPU（如 AutoDL RTX 4090）：约 800 元/月（24 小时运行）
> - 自有 GPU（如学校服务器/自有 RTX 4090）：0 元/月
> - Qwen3-8B 仅需 1 张 RTX 4090（24GB 显存）即可运行

**与其他方案对比**：

| 方案 | RAG 月成本 | 推理月成本 | GPU 成本 | 总月成本 | 数据隐私 |
|------|-----------|-----------|----------|----------|----------|
| **Qwen3-8B 本地 + V4-Pro** | 7 元 | 510 元 | 800 元 | **1,317 元** | ✅ RAG 数据不出服务器 |
| V4-Flash + V4-Pro | 135 元 | 510 元 | 0 元 | **645 元** | ❌ 全部经过云端 |
| Qwen3-8B API + V4-Pro | 135 元 | 510 元 | 0 元 | **645 元** | ❌ 全部经过云端 |
| Qwen3-8B API + V3 | 135 元 | 900 元 | 0 元 | **1,035 元** | ❌ 全部经过云端 |

> 本地部署的核心价值：**数据隐私** + **RAG 零 API 成本**。GPU 算力成本可通过使用学校/自有设备降至 0。

## 3. 各模型分析

### Qwen3-8B（RAG 主力 · 本地部署 · 首选）

**优势**：
- **零 API 成本**：本地部署，RAG 检索不产生任何调用费用
- **数据隐私**：用户学习数据（笔记、教材、提问）全程不出服务器，天然合规
- **无并发限制**：本地部署不受云 API QPS 限制，可根据硬件自定义
- **低延迟**：本地推理无网络传输开销，响应更快
- 中文理解能力在同级别模型中领先，RAG 生态成熟（LlamaIndex / Haystack 原生支持）
- 128K 上下文覆盖 95% 的教材场景（单本教材通常 10-30 万字）
- Apache 2.0 开源许可，商用无限制
- 支持 Tool Calls + JSON Output，RAG 流程编排灵活

**劣势**：
- 需要 GPU 硬件（RTX 4090 / A10G，24GB 显存）
- 128K 上下文无法处理超长文档（整本教材 50 万字+）
- 本地部署需要一定的运维能力

**适用性分析**：
Qwen3-8B 作为 RAG 检索的主力模型极为合适。8B 参数量足以胜任知识点提取、query 改写、语义匹配、检索结果筛选等任务——这些工作本质上是「理解 + 匹配」，不需要深度推理。128K 上下文覆盖绝大多数教材场景。本地部署带来零 API 成本和数据隐私保障，对教育产品是核心优势。

---

### DeepSeek-V4-Flash（长文档兜底 · API · 辅助）

**优势**：
- 1M 超长上下文，可处理整本教材、长篇论文等超长文档
- 2500 高并发，按需调用无压力
- 缓存命中价仅 0.02 元/百万tokens，长文档重复检索成本极低
- 与 V4-Pro 同平台，统一 SDK

**劣势**：
- 调用频率低时缓存命中率不高（首次处理长文档无缓存）
- 数据经过云端（仅在长文档场景使用，风险可控）

**适用性分析**：
V4-Flash 在本架构中是「兜底角色」，仅在用户上传超过 128K 的超长文档时才被调用。预计调用频率仅占总 RAG 调用量的 5% 左右，月成本约 7 元。它的核心价值是补足 Qwen3-8B 上下文长度的短板，确保产品功能完整性。

---

### DeepSeek-V4-Pro（推理生成 · API · 首选）

**优势**：
- DeepSeek 最新旗舰模型，推理能力行业顶级
- 1M 超长上下文 + 384K 最大输出，支持批量出题
- 支持思考模式（thinking mode），复杂推理场景质量更高
- 输出单价 0.006 元/K，低于上一代 V3 的 0.008 元/K
- 缓存机制对教育场景友好：高频知识点重复出题时缓存命中率高

**劣势**：
- 并发限制 500，高并发场景需关注
- 输入单价（缓存未命中）0.003 元/K 高于 V3 的 0.002 元/K

**适用性分析**：
V4-Pro 负责所有需要强推理的任务：出题、解析、口诀生成、知识问答。这些任务对推理质量要求高，是用户体验的核心，必须用最强的模型。缓存机制在教育场景中效果显著——同一知识点被不同学生反复提问时，命中率高，实际成本远低于标价。

---

### DeepSeek-V3（大参数模型 · 备选）

**优势**：
- 成熟稳定，经过大量生产环境验证
- 输出单价 0.008 元/K，略高于 V4-Pro 但差距不大

**劣势**：
- 上下文仅 64K（V4-Pro 为 1M）
- 推理能力弱于 V4-Pro
- 不支持思考模式

**适用性分析**：
如果 V4-Pro 出现服务波动或成本超预期，V3 是最稳妥的降级方案。

---

## 4. 推荐结论

### 首选推荐：Qwen3-8B 本地部署（RAG） + DeepSeek-V4-Pro API（推理）

**推荐理由**：
1. **数据隐私最优**：RAG 检索全程本地处理，用户学习数据（笔记、教材、提问）不出服务器，天然满足教育数据合规要求
2. **RAG 成本趋零**：本地部署 Qwen3-8B 无 API 调用费用，仅长文档兜底（5%）产生约 7 元/月的 V4-Flash 费用
3. **推理质量顶级**：V4-Pro 是 DeepSeek 最新旗舰，出题/解析/口诀生成质量行业领先
4. **延迟体验好**：本地 RAG 推理无网络开销，响应速度快
5. **无并发限制**：本地部署可根据硬件自由扩展，不受云 API QPS 约束
6. **开源可控**：Qwen3-8B Apache 2.0 开源，无厂商锁定风险

**预期效果**：
- RAG 月度成本：约 7 元（仅长文档兜底调用 V4-Flash）
- 推理月度成本：约 510 元（无缓存）→ 257 元（50% 缓存）
- GPU 成本：800 元/月（云 GPU）或 0 元（自有设备）
- 总月度成本：约 517 元（自有 GPU）~ 1,317 元（云 GPU）
- 单次学习 session 成本：约 0.0035 元（自有 GPU）~ 0.009 元（云 GPU）
- 数据隐私：✅ RAG 全程本地，学习数据不出服务器

### 备选方案：DeepSeek-V4-Flash + DeepSeek-V4-Pro（全 API）

**备选理由**：
如果无法获取 GPU 资源（如没有学校服务器、不愿租用云 GPU），可退化为全 API 方案。V4-Flash 负责 RAG，V4-Pro 负责推理，月成本约 645 元（无缓存）。代价是学习数据全部经过云端，隐私保障降低。

## 5. 落地建议

### 5.1 接入步骤

1. **部署本地 Qwen3-8B**：
   - 使用 vLLM / Ollama / llama.cpp 部署 Qwen3-8B
   - 硬件：RTX 4090（24GB 显存）或 A10G，支持 INT4 量化可降低至 16GB
   - 配置 OpenAI 兼容 API 接口，便于与上层代码统一调用
2. **注册 DeepSeek 开放平台**：
   - 获取 V4-Pro 和 V4-Flash 的 API Key
   - 配置到后端环境变量
3. **搭建 RAG 管线**：
   - 文档上传 → 检测长度：≤128K 走本地 Qwen3-8B，>128K 走 V4-Flash API
   - 知识点提取 → 向量化 → 存入向量数据库（Milvus/Chroma）
   - 用户提问 → 本地 Qwen3-8B 语义检索 → 拼接上下文 → V4-Pro 生成回答
4. **开发联调**：先用小流量测试，验证出题质量和问答准确度
5. **上线监控**：配置 GPU 利用率监控、API 用量告警、成本监控

### 5.2 风险提示

| 风险项 | 影响 | 应对措施 |
|--------|------|----------|
| GPU 硬件故障 | RAG 服务中断 | 本地模型不可用时自动降级到 V4-Flash API（临时替代 RAG） |
| V4-Pro API 波动 | 出题/问答中断 | 降级到 V3 API；本地 Qwen3-8B 可临时承担简单问答 |
| 成本超预期 | 推理 API 费用失控 | 设置月度预算硬限 + 用量告警；充分利用 V4-Pro 缓存机制 |

## 6. 产品定价与盈亏分析

> 本节基于第 4 节选型结论中的调用成本推导。假设场景：面向 C 端学生用户的订阅制产品。

### 6.1 产品定价策略

**定价模式**：Freemium + 订阅制

**成本加成定价推导**：
- 选型模型单次学习 session 成本：约 0.0035 元（自有 GPU）/ 0.009 元（云 GPU）
- 假设人均月用量 μ = 150 次 session（每天 5 次）
- 人均月变动成本 = 0.0035 × 150 = **0.53 元**（自有 GPU）/ 0.009 × 150 = **1.35 元**（云 GPU）
- 目标毛利率：85%
- 建议月费（成本加成）= 0.53 × (1 + 0.85) = **0.98 元**（自有 GPU）/ 1.35 × (1 + 0.85) = **2.50 元**（云 GPU）

**实际定价策略**（考虑市场接受度和竞品）：

| 层级 | 月费 | 包含额度 | 超出单价 | 目标人群 |
|------|------|----------|----------|----------|
| 免费版 | 0 元 | 30 次/月（每天 1 次） | — | 体验用户 |
| 基础版 | 9.9 元 | 200 次/月 | 0.1 元/次 | 日常学习 |
| 专业版 | 19.9 元 | 500 次/月 | 0.06 元/次 | 备考冲刺 |
| VIP 版 | 39.9 元 | 不限次 | — | 高频用户 |

**定价依据**：
- 成本底线：0.53 元/月（自有 GPU）或 1.35 元/月（云 GPU）
- 竞品参考：同类 AI 学习工具（如 Kimi 智能助手、豆包）月费 9.9-29.9 元
- 学生支付意愿：单月 <20 元接受度最高

### 6.2 盈亏平衡分析（客户保有量临界点）

**输入假设（自有 GPU 场景）**：

| 参数 | 值 | 说明 |
|------|------|------|
| 固定成本 FC | 2,000 元/月 | 域名 + 运维 + V4-Pro 最低消费（GPU 已有） |
| 单次 session 成本 | 0.0035 元 | V4-Pro 推理（50% 缓存）+ V4-Flash 兜底均摊 |
| 人均月用量 μ | 150 次 | 每天 5 次 |
| 人均月变动成本 | 0.53 元 | 0.0035 × 150 |
| ARPU（加权平均） | 12 元/月 | 免费用户拉低均值 |
| 毛利率（扣除变动成本后） | 95.6% | (12 - 0.53) / 12 |

**盈亏平衡点计算**：
```
N_break_even = FC / (ARPU − 单次成本 × μ)
             = 2,000 / (12 − 0.0035 × 150)
             = 2,000 / (12 − 0.53)
             = 2,000 / 11.47
             ≈ 175 个付费用户
```

**结论**：当付费用户保有量 > 175 人时，业务开始盈利（自有 GPU 场景）。
（假设免费用户占比 70%，则总用户需约 583 人）

**对比：云 GPU 场景**：
```
N_break_even = 5,000 / (12 − 1.35) = 5,000 / 10.65 ≈ 470 个付费用户
```

### 6.4 盈利优化建议

## 7. 实际落地情况（截至 2026-07-17）

> 本节记录项目实际开发中所采用的模型架构，与选型报告推荐方案的差异及原因。

### 7.1 实际架构 vs 推荐架构

| 层级 | 选型报告推荐 | 实际落地 | 差异原因 |
|------|-------------|----------|----------|
| **Embedding** | 未单独讨论 | **BAAI/bge-small-zh-v1.5**（本地 CPU） | 独立于 LLM 的专用向量模型，512 维，~95MB，零成本本地推理 |
| **RAG 检索（LLM）** | 本地 Qwen3-8B | **暂未部署** | 无 GPU 资源；当前用 BGE 向量检索替代，效果可接受 |
| **文档格式化 + 知识点提取（NLU）** | V4-Flash（长文档兜底） | **V4-Flash**（主力 NLU） | Flash 承担了原计划中 Qwen3-8B 的知识点提取任务 |
| **长文档兜底** | V4-Flash | **已合并到 Flash NLU 角色** | 所有文档统一走 V4-Flash 处理 |
| **推理生成（问答）** | V4-Pro | **V4-Pro** | 一致 |

### 7.2 当前 LLM 使用场景明细

| 任务 | 模型 | 温度 | 触发时机 |
|------|------|------|----------|
| 文档 Markdown 格式化 | V4-Flash | 0.3 | 每次上传文档，50K 字符内分批 |
| 知识点提取 | V4-Flash | 0.3 | 文档处理完成后 |
| RAG 问答（找到相关内容） | V4-Pro | 0.7 | 用户提问 → 检索命中 |
| 通用问答（降级） | V4-Pro | 0.7 | 检索无结果时自动降级 |
| 笔记本摘要 | V4-Flash | 0.5 | 用户请求生成笔记本摘要 |

### 7.3 为何暂未部署本地 Qwen3-8B

1. **无 GPU 资源**：RTX 4090（24GB）或同等 GPU 未到位，CPU 推理 8B 模型延迟不可接受
2. **BGE 向量模型已满足 RAG 检索需求**：语义搜索和检索由专用 Embedding 模型完成，无需 LLM 参与
3. **V4-Flash API 成本可控**：初期用户量小，Flash API 月费用远低于 GPU 租用费
4. **接口已预留**：`llm_service.local` 已实现 Ollama 兼容接口，`.env` 中设置 `LLM_LOCAL_BASE_URL` 即可激活

### 7.4 未来迁移路径

当用户量增长、GPU 资源就绪后，迁移路径如下：

```
当前架构                          目标架构
─────────                        ─────────
BGE (embedding)     ──→          BGE (embedding)         [不变]
V4-Flash (NLU)      ──→          Qwen3-8B 本地 (NLU)     [省 API 费]
V4-Flash (长文档)    ──→          V4-Flash (长文档兜底)    [保留]
V4-Pro (推理)       ──→          V4-Pro (推理)           [不变]
```

切换方式：`llm_service.use_local_for_flash()` 即可将 Flash 切换到本地 Ollama 8B。

### 7.5 实际成本参考（当前阶段）

由于用户量极小（开发/测试阶段），以下为单用户月度估算：

| 假设 | 数值 |
|------|------|
| 月上传文档 | 10-20 篇（平均 5000 字/篇） |
| 月提问次数 | 100-200 次 |
| Flash 调用（格式化 + KP） | ~80,000 tokens/月 |
| Pro 调用（问答） | ~200,000 tokens/月 |
| **总计 API 费用** | **< 2 元/月**（缓存命中情况下 < 0.5 元） |
